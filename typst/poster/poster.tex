      \begin{mybox}{What are Leader Election Algorithms?}
        A set of algorithms utilised when a distributed system:
        \begin{enumerate}
          \item relies on single node to be a main database, coordinator, etc,
          \item has no primary node is established, and
          \item when the primary node is offline due to timeouts or network split.
        \end{enumerate}

      \end{mybox}
      \begin{mybluebox}{Bully Algorithm}
        \textbf{Worst Case Time Complexity:} $O(n^2)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item A node requests nodes with a higher ID that it wants an election.
          \item Any response from a greater node makes a sender concede, this greater node holds a new election.
          \item A timed-out response from all greater nodes indicates that a node is the new leader, and it informs other nodes.
          \item When the initiator has the greatest ID, Bully runs in $O(n)$.
        \end{itemize}
      \end{mybluebox}
      \begin{mybluebox}{Paxos Algorithm}
        \textbf{Worst Case Time Complexity:} $O(\infty)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item Features simultaneous proposer, accepter, and learner roles.
          \item Two election phases deciding who proposes and whether their value is accepted.
          \item Best case time complexity of $O(n)$.
        \end{itemize}
      \end{mybluebox}
      \begin{mybluebox}{Raft Algorithm}
        \textbf{Worst Case Time Complexity:} $O(n^2)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item Intended as a Paxos successor; all nodes begin as followers.
          \item Random exponential backoff and timeouts reduce collisions.
          \item Candidates broadcast requestVote() to all nodes and receive results for a best case time complexity $O(n)$.
        \end{itemize}
        \begin{figure}
            \centering
            \input{raftState.tex}
            \caption{A state diagram for the raft algorithm}
        \end{figure}
      \end{mybluebox}
      \begin{myredbox}{Consensus Algorithms can be Leader Elections!}
        The Raft and Paxos algorithms are intended as consensus algorithms. However, with Raft we only the initial leader election phase,
        and for Paxos, we choose the value being agreed upon to be about who is a "leader".
        Thus we can slightly modify these algorithms to focus on leader elections without any correctness or performance changes.
      \end{myredbox}

      \begin{mybox}{Conclusion}
        We have concluded that Paxos is the most efficient of the three algorithms when operating across a cross-continental profile.
        While Raft occasionally performs faster, the random backoff introduces far greater variability and produces many outliters that
        result in a far greater runtime.
        Furthermore, the exponential nature of the bully algorithm is apparent in its far greater growth factor. 
        Overall, we would suggest cross-continental distributed systems perfer Paxos when performing leader election.
