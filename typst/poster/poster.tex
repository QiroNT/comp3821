      \begin{mybox}{What are Leader Election Algorithms?}
        A set of algorithms utilised when a distributed system:
        \begin{enumerate}
          \item relies on a primary node to act as main database, coordinator, etc.
          \item and no primary node is established
          \item or connection to the primary node is lost; either due to timeout or network splitting.
        \end{enumerate}
        \begin{figure}
          %find a way to draw in latex in squished form
          \includegraphics{images/summaryDiagram.png}
          \caption{A single leader maintains consistency, but how can the network recover from the loss of it's leader?}
        \end{figure}
      \end{mybox}
      \begin{mybluebox}{Bully Algorithm}
        \textbf{Worst Case Time Complexity:} $O(n^2)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item A node requests nodes with a higher ID that it wants an election.
          \item Any response from a greater node makes a sender concede, this greater node holds a new election.
          \item A timed-out response from all greater nodes indicates that a node is the new leader, and it informs other nodes.
          \item When the initiator has the greatest ID, Bully runs in $O(n)$.
        \end{itemize}
      \end{mybluebox}
      \begin{mybluebox}{Paxos Algorithm}
        \textbf{Worst Case Time Complexity:} $O(\infty)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item Features proposer, accepter, and learner roles.
          \item All nodes can hold all roles at once.
          \item Has two phases of election, one to decide who proposes some value, then another to get that value accepted.
          \item Best case time complexity of $O(n)$.
        \end{itemize}
      \end{mybluebox}
      \begin{mybluebox}{Raft Algorithm}
        \textbf{Worst Case Time Complexity:} $O(n^2)$\\
        \textbf{Key Features:}
        \begin{itemize}
          \item Intended as successor to Paxos.
          \item All nodes begin as followers.
          \item Random exponential backoff is used along with timeouts to reduce collisions.
          \item Candidates broadcast requestVote() to all nodes and receive results for a best case time complexity $O(n)$.
        \end{itemize}

        \end{figure}
      \end{mybluebox}

      \begin{myredbox}{Consensus Algorithms can be Leader Elections!}
        Technically, the Raft and Paxos algorithms are consensus algorithms, not leader election algorithms.
        However, in the case of the Bully algorithm, only the initial leader election phase needs to utilised and the log replication phase can be ignored.
        As for the Paxos algorithm, we set the values being agreed upon are not database entries but information about who is a "leader".
        Thus we can slightly modify these algorithms to focus on leader elections without any correctness or performance change to the algorithms themselves.
      \end{myredbox}
      \begin{mytealbox}{Testing framework}
        We implemented a testing framework so that our experiment could be indpendent of hardware.
        It provides an API for separate implementations of our algorithms to work on exactly the same network configuration and same communication overhead.
        This also allows us to construct specific network latency profiles and standardise running times to standard theoretical networks instead of CPU cycle speed.
      \end{mytealbox}
